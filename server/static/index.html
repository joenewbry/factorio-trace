Factorio Trace

A public corpus of humans playing Factorio. Screen, mouse, and keys, recorded only while Factorio is the active application. Optional in-game sidecar for tick-accurate factory events.

Why both a recorder and a mod

A Factorio mod cannot see the operating system. Mouse position is not part of the game state, so Lua cannot poll the cursor every frame. game.take_screenshot writes the renderer, not the desktop. That is the right tool for labels. It is the wrong tool for training a computer-use agent.

OS recorder

Captures the Factorio window, mouse, and keys. Pauses the instant Slack, a browser, or the desktop is frontmost. This is what a screen-reading agent actually sees.

Lua sidecar

Writes tick, camera, selected entity, crafts, builds, research, GUI opens, and click positions on linked controls. Ground-truth the pixels cannot give you.

What a mod misses

If we only shipped the mod, these never enter the dataset. That is why the default capture is the Factorio window plus HID, with the mod as an optional second rail.

Record a session

Python 3.10+, Factorio 2.0. On macOS grant Screen Recording and Accessibility to your terminal. On Windows run the same commands from PowerShell.

pip install "factorio-trace[macos]"   # macos extra on a Mac
factorio-trace install-mod            # optional sidecar
factorio-trace doctor
factorio-trace record --contributor yourname --upload --yes

While it runs, alt-tab freely. The log records a pause, drops those keys, and resumes when Factorio is frontmost again. Nothing outside the game is uploaded.
